Detecting a Subarray That Sums to a Target

Lesson 1 · Prefix Sum Pattern · Interview Track Step 3c

Reference: Prefix Sum Cheat Sheet Mission Glossary

You already built a prefix sum array and used it to answer range-sum queries in O(1). This lesson takes the next step: using that same idea to answer "does any subarray sum to a target?" in a single O(n) pass — no nested loops, no precomputed array needed.

The Identity You Already Know

Your RangeSum function works because of one identity:

sum(a[i..j]) = pre[j+1] - pre[i]

The sum of any contiguous slice a[i..j] is the difference of two prefix values. That's the entire mechanical foundation. Everything from here is a rearrangement of this one line.

The Insight

We want to find i and j such that sum(a[i..j]) = target. Substituting the identity:

pre[j+1] - pre[i] = target

Rearrange to isolate what we're looking for:

pre[i] = pre[j+1] - target

Read this carefully. It says: at each position j, the prefix sum we need to have seen earlier is pre[j+1] - target. If some earlier prefix sum equals pre[j+1] - target, the subarray from that earlier point to j sums to target.

This is the whole trick. You don't need to check every pair (i, j). You walk once, and at each step you ask a single question: "have I seen running - target before?"

The Algorithm

Here's the complete procedure for detecting whether any subarray sums to target:

func HasSubarraySum(a []int, target int) bool {
    seen := map[int]bool{0: true}  // empty prefix: sum before any elements
    running := 0
    for _, v := range a {
        running += v
        if seen[running - target] {
            return true  // a subarray from that earlier point to here sums to target
        }
        seen[running] = true
    }
    return false
}

Three things to notice:

  1. One pass, O(n). You never look back at earlier elements — you only check the set.
  2. The set is initialized with 0. This represents the prefix sum before reading any elements (the "empty prefix"). Without it, a subarray starting at index 0 would be missed — more on this below.
  3. You add running to the set after checking. The check is against prefix sums from earlier positions, not the current one.

Why {0}?

At step 2 above, the running sum hit 7 and we checked for 7 - 5 = 0. That 0 was in the set because we put it there before walking. It represents the prefix sum of zero elements — "before you've read anything, the sum is 0." Without it, subarrays that start at index 0 would never be detected — you'd miss the match 2 + 3 = 5 here entirely.

From Detection to Counting

The exercise asks for a second function: CountSubarraysWithSum. This is LeetCode 560, and the change is small but important:

  • The seen-set becomes a seen-map: map[int]int; the value is how many times each prefix sum has appeared.
  • Instead of if seen[...] { return true }, you add counts[running - target] to a running total — every earlier occurrence of that prefix sum is a distinct valid subarray.
  • Initialize with {0: 1} instead of {0: true}.
func CountSubarraysWithSum(a []int, target int) int {
    counts := map[int]int{0: 1}
    running, total := 0, 0
    for _, v := range a {
        running += v
        total += counts[running - target]  // 0 if not present (Go map zero-value)
        counts[running]++
    }
    return total
}
